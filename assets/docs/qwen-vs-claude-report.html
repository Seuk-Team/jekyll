9해석 주의 — 숫자를 과신하지 않기 위해

  • 채점기 편향: 테스트셋·judge.py는 원래 Qwen 학습(gold) 기준으로 만들어져 약간 Qwen 친화적이다. 절대 점수보다 같은 자·같은 편향으로 잰 상대 궤적(26.1 → 69.6 → 73.9)이 유효한 지표다.
  • 표본 크기: 23건은 방향을 보기엔 충분하지만 1~2건 차이(예: 69.6 vs 73.9)는 통계적으로 유의하다고 말하기 어렵다. "v9가 Claude와 동급"이 정직한 표현이다.
  • 단일턴 채점: 다중턴 확인 흐름(검색→확인→실행)을 한 턴에 평가해 Claude write 5건이 저평가됐다.
  • v9 항목별 원자료는 보존되지 않아 총점과 실패 분류만 있다.
정리 — 정확도는 v9가 Claude와 동급(73.9 vs 69.6)까지 올라왔고, 실패의 질도 둘 다 "위험한 실패 0건"으로 안전하다. 갈린 곳은 수치 추론·형식 안정성(요약 어댑터)과 지연·동시성(콜드 78초·대기줄)이며, 이것이 심사 서빙을 클라우드+Claude로 확정한 이유다. Qwen 자체학습은 "public API 없이도 갈 수 있는가"에 실측으로 답한 비용 절감 R&D 자산으로 남는다.
