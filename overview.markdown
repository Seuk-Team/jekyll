## 사업 목적

채용 과정에서 발생하는 반복 업무를 자동화하고, 흩어진 지원자 정보를 하나의 플랫폼으로 통합하여 채용 담당자가 '지원자라는 사람'에 집중할 수 있게 한다.

채용담당자가 공고를 올리고, 지원자가 외부 링크로 지원서·이력서를 제출하면, **아르(AI)가 서류를 자격요건·우대사항·인재상 3축으로 채점해 서류 단계를 자동 판정**하고, 담당자·면접관은 칸반 보드에서 면접 이후 단계를 심사·평가한다. 단계가 바뀌면 지원자에게 메일이 자동 발송되고, 모든 이동에 이력과 평가 기록이 남는다. 최종 합불만은 항상 사람이 확정한다(ADR-0003·0034).

그 위에 **도구 호출 AI 에이전트(아르)** 를 얹는다 — "백엔드 공고에서 3년차 이상 찾아서 상위 2명 면접으로 올려줘" 같은 자연어 한 문장이 검색 → 조회 → 단계 변경으로 분해되어 순차 실행되고, 쓰기 작업은 반드시 사람의 확인을 거친다.

## 시스템 개요 — 한 장면으로

1. 채용담당자가 공고를 등록하면 **공개 지원 링크**가 생성된다. 지원자는 로그인 없이 지원서를 작성하고, 이력서는 presigned URL로 브라우저에서 S3로 바로 올라간다 — 파일이 서버를 거치지 않아 부담과 유출 접점이 함께 줄어든다. 이력서·자소서의 SHA-256 은 추가 전용 무결성 원장에 기록되고 사슬 머리가 매일 Ethereum Sepolia 에 앵커된다(ADR-0028).
2. 접수 즉시 **AI 요약·평가·추천 3단 체인**(ADR-0022)이 돌아 요지·핵심 역량·강점·우려와 **3축 점수**를 저장하고, 임계(기본 60) 이상은 면접으로·미만은 서류 탈락으로 **자동 이동**한다(ADR-0034). 자료가 부족한 지원자도 지어내지 않고 서류 탈락 처리한다. 폼에 경력을 안 적었으면 이력서에서 추출해 「AI 추정」 표식을 붙인다.
3. 담당자·면접관은 **칸반 보드**에서 카드를 드래그해 단계를 옮긴다. 모든 이동은 누가·언제·왜까지 이력으로 남는다. 안내 메일은 API 가 n8n 웹훅으로 넘겨 SMTP 로 보내고, n8n 이 멈춰도 API 가 5분마다 밀린 메일을 재발송한다 — 화면 응답이 메일을 기다리지 않는다.
4. 면접 일정은 아르가 면접관 가용 시간을 보고 후보를 제안하고, 지원자는 메일 링크 또는 이메일 + 생년월일 로그인(ADR-0033)으로 24시간 접속해 일정을 고른다. 기본 질문은 FAQ 챗봇이 규칙 응답($0)으로, 나머지는 공고·회사 프로필을 근거로 답한다.
5. **AI 면접**은 지원자가 이력서·자소서 기반 맞춤 질문에 음성으로 답하고, 담당자는 1:1 WebRTC 실시간 화면에서 답변이 서류와 일치하는지 대조 결과를 즉시 본다. 표정(ViT + MediaPipe)·음성 신호는 **담당자 참고 지표로만** 표시되고 점수·합불에 쓰지 않는다(ADR-0029·0032).
6. 종합평가 화면에서 서류·인적성·면접을 한 번에 보고, 담당자가 최종 합격·불합격을 확정한다.

## 채용 단계 모델 — 단계는 다섯, 규칙은 여섯

`지원 접수(applied) → 서류 검토(screening) → 면접(interview) → 최종 합격(accepted) / 불합격(rejected)`

| 규칙 | 내용 |
|------|------|
| 전진은 한 칸씩 | 단계를 건너뛰는 전진은 허용하지 않는다 |
| 역행은 항상 허용 | 사람이 AI 판정을 되돌리는 것이 유일한 안전장치다 |
| 불합격은 어느 단계에서든 | 단, 사유(reason) 없으면 422 — 사유 없는 이력은 나중에 아무도 설명할 수 없다 |
| 서류 단계는 AI 가 자동 판정 | 3축 100점 채점 · 임계 60 · 자료 부족은 서류 탈락. **사람이 한 번 손대면 그 지원자는 이후 자동 판정에서 빠진다 — 수동이 항상 이긴다**(ADR-0034) |
| 일괄 변경은 전부 아니면 전무 | 200명 중 30명만 바뀌면 담당자가 무엇이 됐는지 알 수 없다 → 전체 롤백(409) |
| 사용자는 지우지 않는다 | 비활성화만 — `changed_by`·`evaluator_id` 로 박힌 이력을 물리 삭제가 부순다 |

단계는 DB enum 이 아니라 코드 상수 + 체크 제약으로, 전환 규칙은 서비스 레이어가 강제한다. 마감·만료는 크론이 아니라 **조회 시점에 판정**한다.

## AI 적용 원칙

**버튼으로 되는 일에는 AI를 쓰지 않는다.** 비정형 문서 이해, 자연어 요청의 작업 분해처럼 버튼으로 안 되는 일에만 쓴다.

| 원칙 | 내용 |
|------|------|
| 최종 합불은 사람의 것 (ADR-0003 → 0034) | 서류 단계 이동은 AI 가 하되, **최종 합격·불합격은 사람만** 확정한다. 자동 탈락 메일은 즉시 안 나가고 마감 뒤 담당자가 일괄 발행(번복 여지). UI 문법(앰버 점선 = AI 제안 / 실선 = 사람 확정) |
| 쓰기 확인 강제 | 읽기 도구는 즉시 실행, 쓰기 도구(단계 변경·면접관 배정·메일 발송)는 확인 카드로 반환되어 사람이 승인해야 실행된다 |
| 근거 기반 응답 | 에이전트 응답은 도구 결과·이력서 원문만 인용한다. 채용과 무관한 질문은 "답의 근거가 우리 데이터냐" 를 기준으로 내용 없이 거절. 면접 분석은 STT → 근거 대조 → Claude 로, 근거 없이 단독 판단하지 않는다 |
| 표정·음성은 참고 지표까지만 (ADR-0029) | 담당자 화면에 수치로 보이되 **점수 재료가 아니다.** AI 요약 문장도 측정 수치의 재서술만 허용 — 수치에 없는 숫자나 사람을 단정하는 단어가 나오면 문장을 버리고 고정 틀로 대체 |
| 모델은 같은 자로 재고 결정 | Qwen3-8B QLoRA 자체학습(3어댑터)과 Claude 를 **동일 채점기·동일 23건**으로 비교(26.1% → 69.6% → 73.9%). 정확도는 동급이었으나 수치 추론·형식 안정성·지연·동시성 리스크로 클라우드 + Claude 확정(09-18). 근거는 [Qwen vs Claude 보고서](/assets/docs/qwen-vs-claude-report.html) |
| 비용·품질 관측 | 프롬프트 18개를 코드로 버전 관리, 호출마다 모델명·토큰 로깅(실측 아르 호출당 $0.0075). 인사·능력·기본 FAQ 는 규칙 라우터가 LLM 없이 $0. 대량 더미 데이터에는 AI 호출 금지 |
| 개인정보 | 프롬프트에 연락처·주민번호 미포함. 실시간 면접 음성은 서버 내 로컬 전사, 아르 음성 입력·업로드 재전사는 OpenAI API — 경로는 `STT_BACKEND` 로 명시(ADR-0038) |

## 추진 체계 — 도메인 오너제

한 사람이 도메인 하나를 소유하고, 자기 도메인 로드맵이 작업의 기준이다(ADR-0007). 팀장은 승인 게이트가 아니라 자원·비용·발표 문구만 조율하고, 금요일 주간 다이제스트는 검수가 아니라 파악용이다.

| 도메인 | 담당 | 범위 |
|--------|------|------|
| 인프라·총괄 | 진수택 (팀장) | AWS·자동 CD·CI·관측·발표 총괄 · 모델 전략(Qwen 학습 → 클라우드 확정) · 데모 설계 |
| 백엔드 | 이우정 | 코어 API(인증·공고·지원서·평가·검색)·단계 전환 규칙·메일·무결성 앵커·실시간 면접 백엔드·DB 권한 분리 |
| 에이전트 | 박소연 | 도구 호출 에이전트·AI 요약·RAG·이력서 구조화 추출·표정/거짓 신호 서비스 |
